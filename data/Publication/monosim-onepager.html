Overview

MonoSIM is a lightweight SIL testbed that makes autonomous lane-keeping research accessible and reproducible. It emulates a single-camera Ackermann car in the MVSim (2.5D, Box2D) simulator over ROS 2, with minimal computational overhead, targeting small-scale low-cost platforms (e.g. XTENTH-CAR) for research and education. A shared, deep-learning-free vision pipeline recovers lane geometry; interchangeable controllers then steer — isolating a clean comparison: same perception, same vehicle, same track — different control law.

System Architecture

The two controllers

PID

Reactive baseline
  • Steers on instantaneous lateral error of the detected lane center
  • Model-free; fixed cruise velocity
  • Near-constant speed, but spikes in angular velocity

MPC

Predictive optimizer
  • 3-DOF dynamic bicycle + linearized Pacejka tires → state-space
  • Incremental MPC, quadratic Q/R cost over horizon, constrained
  • Smoother, constraint-aware control

Results — PID vs MPC

Multiple trials on randomly generated sinusoidal-curvature tracks (Ubuntu 24.04, Intel Core i7). Mean squared deviation across all runs:

MetricPIDMPC
Lateral MSD (m²)0.01360.0390
Angular MSD (rad²)0.0005480.001014

PID minimizes raw tracking error; MPC trades some accuracy for smoother, more robust, constraint-aware control. The testbed cleanly reflects the genuine difference in control behavior.

Technical Highlights

  • Transparent, compute-light perception — a fully classical CV pipeline (DLT-homography calibration with a 5×4 chessboard + subpixel corners, bird's-eye warp, HSV V-channel isolation, sliding-window search, polynomial fitting) recovers metric lane geometry from a single low-res camera, no deep learning.
  • Model-based MPC — a 3-DOF dynamic bicycle model with a linearized Pacejka tire model, cast to discretized state-space and posed as an incremental MPC with a manually tuned quadratic (Q/R) cost under actuator/state constraints.
  • Real SIL experiment harness — one launch stack swaps PID/MPC over identical simulation, vehicle, and world configs; odometry is logged to CSV for offline mean-squared-deviation analysis.
  • Faithful behavior discrimination — the framework measurably separates a low-error reactive controller from a smoother, constraint-aware predictive one — its core validation.
  • Metric grounding — monocular calibration maps image pixels to physical points, analogous to learned depth/segmentation, so control reasons in real units.

Package Layout

  • mpc_control_node.py — perception + MPC loop, marker viz
  • mpc_optimizer.py — convex QP solver (do_mpc)
  • pid_control_node.py — perception + PID loop
  • odometry_plotter_node.py — live plots + CSV logging
  • launch/ — mpc, pid, simulation
  • description/ — Ackermann vehicle + camera sensor
  • worlds/ — track & calibration worlds

Run It

  • colcon build in your ROS 2 workspace
  • ros2 launch monosim mpc.launch.py
  • ros2 launch monosim pid.launch.py velocity:=2.5
